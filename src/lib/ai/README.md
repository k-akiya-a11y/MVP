# src/lib/ai

Claude API の呼出し、プロンプト（版を固定）、出力 JSON のスキーマ検証。AI は提案を返すだけで、ここから外部書込を起動しません。
モデルとプロンプトの版は `version.ts`、回答形式は `schema.ts`、AI に送る前の伏字は `mask.ts`、マスタとの照合は `validate.ts`。

## プロンプトの信頼境界（版 `journal-proposal/2026-10-24.1`）

- **system**: 固定の指示だけ（`prompt.ts` の `INSTRUCTIONS`）。顧客・マスタ・メモ・明細・過去仕訳など、外部から来る値や顧客ごとに変わる値は入れない。入力が何であっても同じ文字列。
- **user**: 参考データを `JSON.stringify` した文字列1通（customer の課税方式・インボイス、masters、notes、transaction、past）。引用符・改行・`</system>`・役割を装った文面は JSON の文字列値の中にとどまり、構造や API の役割は作れない。null（値がない・未設定。現実に存在しないことの確認ではない）とキーなし（情報なし）は区別して渡す。
- **伏字**: 自由記述（メモの題名・本文、マスタ名、口座名、摘要、取引先キー）はすべて `maskSensitive` を通してから JSON にする。顧客名・顧客ID・口座番号・残高は送らない。
- **キャッシュ**: 以前は顧客情報・マスタ・メモを system に置いて `cache_control` を付けていたが、顧客データを system に置かなくなったため system のキャッシュ指定はなくなった。user のデータを system に戻してキャッシュする構成にはしない。入力トークンの割引が減るので、費用は実測で見直す（設計書の費用の前提も参照）。
- 注入への耐性は保証しない。モデル・クライアント・スキーマ・マスタ検証・承認は変えていない。実モデルでの正答率と注入文の評価は**本番公開の前に必須で、未実施**（`tests/unit/prompt-trust-boundary.test.ts` はモックによる組み立ての確認のみ）。

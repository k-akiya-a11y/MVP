# src/lib/statements

銀行・カード明細 CSV の読取と取込。形式（列の見出し・文字コード）は `formats.ts` に銀行・カード会社ごとに足します。1行でも読めない行があればファイル全体を取り込みません。CSV の書式が壊れているとき（閉じられていないクオート、値の途中のクオート、閉じクオートの後ろの余分な文字）や、行の列数が合わないとき（途中で切れた行、見出しより右に値がある行）も、読めた行だけを取り込まず、行番号つきの失敗として記録します。

金額は整数の円だけを受け付けます。先頭に `¥` か `\` を1つ、末尾に `円` を1つまで付けられ、3桁区切りのカンマは正しい位置のものだけ有効です。`1,23` `1,,234` `1円2` `1 2` のようにカンマの位置が不正、数字の途中に記号や空白がある金額は、連結して別の金額にせず誤りとし、1行でもあればファイル全体を取り込みません。この検査より前に取り込まれた誤った金額は自動では直りません。

見出し行で、同じ意味（日付・摘要・出金・入金・金額・残高）に当たる列が2つ以上あるとき（例: `出金` と `出金額` が両方ある）は、最初の列だけを使って残りを黙って無視せず、行を読む前にファイル全体を、見出し行の行番号つきの失敗として記録します。無関係な列や、同じ列が複数の別名に当たるだけの場合は影響しません。この検査より前に取り込まれた明細は自動では直りません。

出金と入金を別の列で持つ形式（銀行）では、両方の見出しが必要です。片方しか認識できないと、認識できない側の金額が空欄（0円）として読まれて取引が黙って捨てられるため、行を読む前にファイル全体を、見出し行の行番号つきの失敗（「入金」または「出金」の列が見つかりません）として記録します。両方ないときは従来どおり「金額の列が見つかりません」、符号付き金額1列のカード形式は対象外です。両方の見出しがあれば、行ごとの空欄・0円や残高なしは従来どおり読めます。この検査より前に取り込まれた明細は自動では直りません。

符号付き金額1列の形式（カード）では、金額欄の空欄と明示的な0を区別します。空欄（空文字、ASCII 空白・全角空白だけ、クオートされた空欄）は金額が不明なので、その行を「金額が空欄です」の行エラーにします。`0` と全角の `０` は従来どおり金額0として `ignored` に入れ、エラーにしません。エラーが1件でもあるファイルは既存の `errors` の検査で取込全体が失敗し、`importRows` は呼ばれません。返金（負の金額）と、出金・入金を別の列で持つ銀行形式の空欄の扱い（両方空欄 = 金額0 = `ignored`、片方空欄は値のある側を使う）は変わりません。この修正より前に取り込まれたデータは自動では直りません。

摘要に NUL（U+0000）を含む行は、PostgreSQL の text 型に保存できないため、金額0の行も含めて `ignored` にせず、物理行番号つきの行エラーにします（値の除去・置換はしません）。エラーが1件でもあるファイルは取込全体が失敗し、`importRows` は呼ばれません。他の制御文字（タブ・改行など）は従来どおりです。

重複キー（口座・日付・入出金・金額・摘要・残高・同一内容の連番）はファイルごとに連番を数え直すので、キーが同じでも同一取引とは限りません。取込済みと同じキーの行を読み飛ばすのは、取込全体が同じ内容の再実行だと DB が確かめられたときの残高のある行だけで、それ以外は「重複の疑い」として人の確認に回します。DB への登録は `import_bank_statement`（担当者の権限、RLS あり）で行い、外部への書込はしません。

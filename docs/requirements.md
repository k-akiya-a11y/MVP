結乃社 AI経理プロジェクト MVP開発依頼

## 1. 今回やりたいこと

結乃社で現在人が行っている経理業務の一部を、
AI＋各種APIを使って自動化したいです。

参考動画で行われている、

- 会計ソフトへの仕訳処理
- 請求書作成
- メール下書き作成

などの自動化を参考にしつつ、
単なるコピーではなく、

「結乃社の経理BPO業務そのものをAI化する」

ことを目的にします。

最終的には、

証憑・銀行・カード・売上データ
↓
AIによる判定
↓
会計処理
↓
請求
↓
入金確認
↓
月次決算
↓
財務分析

までつながる仕組みにしたいです。

ただし、最初から全部作る必要はありません。

まずMVPを作って、
結乃社自身または既存顧客1社で実際に運用し、
どこまで人間の作業時間を減らせるか検証します。


# 2. MVPで作りたい機能

優先順位は以下です。

## ① 銀行・カード明細 → 仕訳候補

銀行・クレジットカード等の取引情報から、

- 取引先
- 摘要
- 金額
- 過去仕訳
- 顧客ごとの経理ルール

などをAIが参照し、

- 勘定科目
- 補助科目
- 税区分
- 部門
- 摘要

等を推定する。

最終的にfreee等の会計ソフトへ連携できる状態を目指す。


## ② 証憑 → 仕訳候補

領収書・請求書等を読み取り、

- 日付
- 取引先
- 金額
- 消費税
- 支払内容

を抽出。

AIが仕訳候補を作成し、
証憑と取引を紐付ける。


## ③ 請求データ → 請求書作成

契約・請求ルール等から、

「今月どこに何円請求するか」

を判定し、
請求書作成まで行う。


## ④ 請求書 → メール下書き

作成された請求書をもとに、

- 宛先
- 件名
- 本文
- 添付ファイル

を設定したメール下書きを自動作成する。

最初は自動送信しない。

人間が内容を確認して送信する。


## ⑤ 入金確認 → 未入金一覧

銀行明細と請求データを照合し、

- 入金済
- 未入金
- 金額不一致
- 名義不一致
- 確認必要

などを自動判定。

人間が確認すべきものだけ一覧化する。


# 3. 一番重要な設計思想

「全部AIにやらせる」ではなく、

人間が確認しなくていい仕事だけを
AIに任せる仕組みにしたいです。

例えばAIの判断について、

高確信
→ 自動処理

中確信
→ 人間がワンクリック承認

低確信
→ 経理担当者へ確認

というHuman Approvalを入れたいです。

確信度の閾値は運用しながら決めます。

重要なのは、

「AIが間違えない」

を目指すのではなく、

「AIが判断できないものだけ人間に回す」

設計です。


# 4. 顧客別ルールを持たせたい

会社によって経理処理が違うので、

各顧客について、

- 過去仕訳
- 勘定科目ルール
- 補助科目
- 部門
- 税区分
- 取引先
- 摘要ルール
- 月次処理
- 請求ルール
- 例外処理

などを持たせたいです。

つまり、

「一般的な会計知識だけで仕訳するAI」

ではなく、

「この会社では、この取引をどう処理するか」

を学習・参照できる仕組みにしたいです。


# 5. AIに持たせたいデータ構造

イメージとして、

会社
↓
経理ルール
↓
過去仕訳
↓
現在の取引
↓
AI判断

という構造。

AIには毎回すべての過去データを渡すのではなく、

現在の取引に近い過去仕訳や
関連ルールを検索して渡す方式を検討してください。

RAG等を使うかどうかは技術的に判断してもらって大丈夫です。


# 6. AI判断ログ

これは必ず残したいです。

最低限、

- AIが受け取った取引
- AIが提案した処理
- 確信度
- 参照したルール
- 参照した過去仕訳
- 人間が承認したか
- 人間が修正したか
- 修正内容
- 処理日時

を記録したいです。

人間が修正したものは、
将来的に次回以降のAI判断改善に使えるようにしたいです。


# 7. 最初から完全自動化しない

Phase1では、

AI
↓
処理案
↓
人間確認
↓
実行

でOKです。

精度が確認できた処理だけ、

AI
↓
自動実行

へ移行します。

特に、

- 仕訳確定
- 請求書送信
- 会計データ変更
- 金銭に関係する処理

については、
初期段階ではHuman Approvalを残してください。


# 8. 想定する技術

ここはKenくんに最適な構成を考えてほしいです。

候補としては、

- Claude / Claude Code
- OpenAI API / Codex
- freee API
- Gmail API
- Google Drive
- Google Sheets
- Supabase
- n8n

等。

ただし、

「AIをたくさん使うこと」

が目的ではありません。

最もシンプルで、
保守しやすく、
顧客数が増えても運用できる構成を優先してください。


# 9. 最初の検証

まず、

「結乃社自身」

または

「業務内容を把握できている既存顧客1社」

でテストしたいです。

導入前に必ず、

各作業について

- 月何件
- 月何時間
- 1件何分

を計測してください。

導入後も同じ指標を取ります。


# 10. MVPのKPI

特に見たいのは、

① 作業時間削減率

② AI自動処理率

③ AI提案の正答率

④ 人間確認率

⑤ 人間による修正率

⑥ 月次決算完了までの日数

⑦ 1社あたり人間作業時間

です。

最重要KPIは、

「1社の経理を処理するために、
人間が何時間必要だったか」

です。


# 11. MVP成功条件

例えば、

導入前
1社 月15時間

↓

導入後
1社 月5時間

になれば、

約67%の省力化。

この数字を実測したいです。

最初から100%自動化する必要はありません。

人間作業時間を50%以上削減できれば、
まずMVPとして十分成功と考えます。


# 12. 将来像

MVPが成功したら、

仕訳
↓
請求
↓
入金
↓
月次決算
↓
財務分析
↓
経営判断支援

まで拡張したいです。

最終的にはGOJKにもつなげ、

「経理をAI化する」

だけではなく、

「経理データから経営判断までつなげる」

ところまで持っていきたいです。


# 13. 商品化イメージ

SaaSを単体販売するというより、

「AI経理＋結乃社の経理品質管理」

として提供するイメージです。

つまり、

ソフトを渡して終わり

ではなく、

AI
＋
結乃社の経理ノウハウ
＋
Human Approval

をセットにする。

結乃社の既存経理BPOを
AIによって高生産性化することが第一目的です。


# 14. Kenくんに最初にお願いしたいこと

いきなり開発開始ではなく、
まず技術設計をお願いします。

以下を出してください。

1. MVPシステム構成図
2. 使用するAI/API/DB候補
3. freeeとの連携方法
4. Gmail等との連携方法
5. 顧客別経理ルールの保存方法
6. 過去仕訳の参照方法
7. AI確信度・Human Approvalの実装方法
8. AI判断ログの保存方法
9. セキュリティ設計
10. MVP①〜⑤それぞれの開発難易度
11. 開発順序
12. MVP完成までのおおよその期間
13. 月額ランニングコスト概算
14. 技術的に難しい部分・リスク

その設計を見てから、
MVPの実装範囲を最終決定しましょう。

今回のゴールは
「すごいAIを作ること」ではありません。
結乃社の実務を実際に減らして、

人が15時間やっている仕事を
5時間にできるのか。

まずそこを実証することです。

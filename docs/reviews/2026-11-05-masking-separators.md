# 伏字が括弧・タブ・改行などの区切りの番号を見逃す: 実装前の期待記録

作成: 2026-11-05（テストを書く前の期待の記録だけ。本番コードは未変更）。実装後にこの節を書き直さない。期待が誤っていた場合は、末尾に日時と理由を追記する。

## 目的

`maskSensitive`（`src/lib/ai/mask.ts`）は、AI に送る自由記述から長い数字を `*` にする（CLAUDE.md 7章「口座番号などは伏せる」）。現状は次の3つだけを伏せる。

- 4桁ずつ空白（半角・全角1つ）区切りのカード番号形式（3〜4グループ）
- 連続またはハイフン区切りで、数字が7桁以上のもの

そのため、次は伏せられずにそのまま AI に送られる（**現状の実装の読解による予測。Claude は実行していない**）。

- 電話番号の括弧区切り: `090(1234)5678`、`090（1234）5678`
- カード番号の区切りがタブ、改行、2つ以上の空白、NBSP（U+00A0）のもの

この段階では**期待の記録と、失敗するはずの回帰テストの追加だけ**を行う。本番コードは変えない。

## 期待する動作

### 伏せる対象と方法

- 対象の形式（すべて半角・全角の数字どちらでも可）:
  - **電話番号**: 数字の塊を括弧 `(` `)` / `（` `）` で区切った形。例 `090(1234)5678`、`090（1234）5678`、`０９０（１２３４）５６７８`、`03(1234)5678`。
  - **カード番号**: 4桁ずつ3〜4グループを、空白類の並び（タブ、改行 `\n`・`\r\n`、半角/全角/NBSP の空白、それらが2つ以上続くもの、混在）で区切った形。
- 特定した**番号の全体**を、**元の文字数と同じ数の `*`** に置き換える。数字だけでなく、その番号の内側にある区切り（括弧・タブ・改行・空白）も `*` にする。既存のハイフン区切り・空白区切りと同じ「長さを保つ」方式を踏襲する。
- 特定した番号の**数字は1文字も残さない**（一部だけ伏せない）。出力に元の断片（`1234`、`5678`、`4111` など）が残らない。
- 番号の前後の文字（日本語、記号、番号の外側の括弧や改行）は変えない。1つの文に複数の番号があれば、それぞれ別に伏せる。

### 変えないもの（過剰に伏せない）

- 日付・短い数字: `10/03 12345`、`3名 1,234円`、`No.12345`
- 通常の括弧・短い数字: `（株）`、`第(1)(2)条`、`TEL(1234)`、`03(12)`
- 通常の改行・タブで区切られた短い数字: `支払\n10/03\n12345`、`1\t2\t3`
- 既存の伏せ方（連続7桁以上、ハイフン区切り、空白1つ区切りのカード番号）の結果。

| `電話090（1234）5678まで` | 同上（13文字） |

| `10/03 12345`、`TEL(1234)`、`1⇥2⇥3` | 変更なし |

- 送信される JSON を `JSON.parse` した各項目が、**期待する完全な伏字の文字列と一致**する（「元の文字列が消えた」だけでは合格にしない）。

## 例外・失敗時の扱い

- 伏字は純粋な文字列変換で、失敗して例外を出す経路を作らない。判定を迷う入力は、既存の挙動（変えない）を優先する。
- 区切りの判定が曖昧な長い文章（番号に見えるが実は別の意味の数字）は、過剰に伏せる側に倒れうる。判定に必要な金額・日付は別の構造化項目で渡すので、摘要内の長い数字を伏せる損失は小さい（`mask.ts` の方針どおり）。

## 変更しない範囲

- Human Approval、確信度の計算、マスタ外の値を弾く処理。
- DB、マイグレーション、外部サービス。
- 既に送信済みのデータの扱い（調査・対応はコード修正と分けた別作業で、Ken の判断が必要）。

## この記録が主張しないこと

- 任意の個人情報（氏名、住所、メールアドレス、マイナンバー、海外の番号形式、ドット区切りなど）を検出できることは**主張しない**。対象は上に列挙した括弧区切りの電話番号形式と、空白類区切りのカード番号形式だけ。

- 伏字は AI へ送る内容の最小化の一手段であり、情報漏えいの防止を保証するものではない。

### 実装（最小の変更）

変更は `src/lib/ai/mask.ts` の `maskSensitive` だけ。プロンプト、モデル名、版、`prompt.ts`、全文の正規化は変えていない。

データの流れ: `buildJournalPrompt` が自由記述（`src/lib/ai/prompt.ts:46,58,65,73,96,99,102`）を `maskSensitive` に通す → 次の3つの置換を上から順に適用 → JSON にして AI へ送る。

1. カード番号（`src/lib/ai/mask.ts:13`）: 4桁 + (空白類の1つ以上 + 4桁) を2〜3回。区切りを半角空白・全角空白1つから `\s+`（タブ、改行、CRLF、複数空白、NBSP、全角空白、それらの混在）に広げた。一致全体を同じ長さの `*` にする。
2. 括弧区切りの電話番号（`src/lib/ai/mask.ts:15-17`、新規）: 数字2桁以上 + `(`/`（` + 数字1〜4桁 + `)`/`）` + 数字4桁以上。数字の合計が7桁以上のときだけ、括弧も含めて同じ長さの `*` にする。この7桁は既存のハイフン規則（`src/lib/ai/mask.ts:19-21`、変更なし）に合わせた。
3. ハイフン区切りを含む7桁以上（変更なし）。

順序の理由: カード番号を先に処理し、空白類で区切られた番号を電話番号・ハイフン規則と競合させない。

### 正規表現の限界と過剰な伏字（保守的な側に倒す）

- 対象は、括弧区切りの電話番号と、4桁ずつ空白類で区切ったカード番号の2形式だけ。ほかの区切り（ドット、スラッシュ、スペースなしの混在、`+81` 付きなど）、4桁以外の区切りのカード番号（例: 4-6-5桁）は対象外で、網羅的には検出しない（既存の「連続7桁以上」の規則により、たまたま伏せられる場合はある。例: 連続12桁のマイナンバー）。
- 氏名、住所、メールアドレス、海外の番号形式などは検出しない。マイナンバーなども、連続7桁以上などの既存規則に当たる形のときだけ伏せられ、網羅的には検出しない。**任意の個人情報が伏せられるとは主張しない**。プロンプトインジェクションへの耐性も、この変更の範囲外である。
- 過剰に伏せる例: 4桁の数字が3〜4個、空白や改行だけで並ぶもの（例: 西暦 `2026 2026 2026`、複数行に並んだ4桁の数字）。数字が続く長い塊の途中にある番号は、先頭の数字も含めて伏せる。`(` の前後の数字だけで7桁以上になる式（例: `12(3)4567`）。判定に必要な金額と日付は別の構造化項目で渡すので、この損失は小さいと判断した。
- 逆に、5グループ以上のカード番号は先頭の3〜4グループだけが伏せられ、残りは残る（既存の挙動と同じ）。
- `\s+` は上限がなく、空行をはさんで離れた4桁の数字も1つの番号とみなしうる。これも伏せる側に倒れる動作で、今回は許容した。

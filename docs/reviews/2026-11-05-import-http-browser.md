作成: 2026-11-05。Codex が現行ソースを隔離したローカルUIコピーで実際に操作した結果の事実記録。製品コード・テストは変更していない。全体のリリース承認ではない。

## 目的

従来の検証は DB 単体のテスト（疑似的な通信断・2セッション）だった。今回は次の 2 点を、実際の HTTP ソケット切断と、実ブラウザの 2 タブ multipart 送信で確認した。

1. 取込は確定したが応答がブラウザに届かなかった場合の UI と DB の状態。
2. 同じ CSV を 2 タブからほぼ同時に送信した場合の結果。

## 再現手順（高水準。秘密情報は含まない）

前提: 合成管理者でログイン済み。顧客1件・口座1件を用意。CSV は合成の残高付き銀行形式（4 行、合計 371,800 円）。ブラウザはプロキシ（3102）経由でアプリへ接続。

### 結果1: 応答喪失

1. ヘルパーの制御で `drop-next` を設定（次の 1 リクエストについて、上流の応答を全文受信後、ダウンストリームをレスポンスヘッダー送信前に破棄）。
2. 取込画面で CSV を選び、1 回クリックする。
3. 画面の状態を確認し、アプリケーションの `router.refresh`（同一のマウント済みフォーム）後も警告と操作の無効状態が維持されるかを確認する。ブラウザのページ全体の再読込後にロックが維持されることは検証対象としていない。
4. DB を読み取り専用で集計する（明細件数・状態、取込記録数、AI/人手確認/実行の各件数）。
5. 履歴画面を開く。

### 結果2: 同一 CSV の 2 タブ同時送信（確定済み）

1. ブラウザタブを明示的に `reload` する（フォームがリセットされ、自動の POST は発生しない）。
2. 別々のブラウザタブを 2 つ開き、同じ確定済み CSV を両方で選択する。
3. ヘルパーの制御で `pair-next` を設定（次の 2 リクエストを揃えてから上流へ同時に送る）。
4. 両タブで送信をクリックする。
5. 各タブの表示と DB の読み取り専用集計を確認する。

### 結果3: 日付とLFのみ異なる新規 CSV の 2 タブ同時送信

1. 合成 CSV を新規作成: 日付を 10/27〜30 から 11/10〜13 に変更、他の内容は同一、改行のみ LF。BOM `EFBBBF` あり。SHA-256 `49BBBD384C0E21FDFA57F6984F276184A2E83FF781D9DF5F4178E3E7D3652CE3`。元CSVとの差が日付と改行のみであることを確認済み。
2. 結果2と同じ手順（2タブで選択、`pair-next`、両方クリック）。
3. 各タブの表示と DB 集計を確認する。

## 観測結果

### 結果1

- ファイル選択ダイアログの初回呼び出しは、承認・ツール待ちで 1599 秒後に完了。復帰前に送信はされていない。以降の選択は正常に完了。
- 実ブラウザで 4 行・銀行 CSV・371,800 円を送信。プロキシ r1 は上流から 200 `ok:true` を全文受信後、ヘッダー・本文の送信前にダウンストリームを破棄。
- UI は「結果不明」の警告を表示。既存の「登録の可能性あり」表示と 4 つの操作が無効の状態が、アプリケーションの `router.refresh` 後（同一のマウント済みフォーム）も維持された。
- 結果2の前に行った明示的なブラウザタブの `reload` では、フォームがリセットされ操作は有効に戻り、自動の POST は発生しなかった。ページ全体の再読込後にロックが維持されることは確認しておらず、主張しない。
- DB: 新規明細 4、取込記録 1、AI 0、人手確認 0、実行 0。自動再試行なし。プロキシが見た対象は 1 件。
- 履歴画面は成功 1 件（4 件 / 371,800 円）を表示。

## 判断

- 実 HTTP ソケット喪失と、実ブラウザ 2 タブの multipart 同時送信を確認した。従来の純 DB テストでは確認できなかった範囲。
- 二重登録・金額の不一致・疑いの誤計上は観測されなかった。確認した範囲では対応が必要な不具合は見つからず、製品コードは変更していない。

## 限界

- 1 種類の残高付き銀行形式、同一の合成管理者のみ。全 CSV 形式、残高なし CSV のブラウザ検証、別ユーザー間の同時送信は未確認。
- 同時性はプロキシによる送出の同期であり、DB ロックの待ちを観測したものではない。ロックの証明は既存の DB テストによる。
- スクリーンショットはツール経由で確認したのみ。画像ファイルは保存していない。
- 前回の 648 単体テスト + 15 DB テスト・型チェック・lint は、製品・テストに変更がないため今回は再実行していない（単体・型・lint は未再実行）。今回は `node --check`、拒否動作の確認（deny probes）、実ブラウザ検証、DB の読み取り専用検証を実際に実行し、差分チェックも合格した。

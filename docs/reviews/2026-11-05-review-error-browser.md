## 再現の方法

- 既知の拒否: 画面を読み込んだ後に別の認証済み RPC で同じ明細を承認し、画面で承認する。
- 想定外エラー: 合成 DB にだけ、特定の明細の人の確認の挿入で XX000 を出すローカル専用トリガーを置く。まとめて承認と単独承認の両方を試す。
- 復旧: トリガーと関数を削除し、再読み込みして確認待ちを確認し、再度選択して承認する。

## 限界

- 失敗は実際の XX000 の DB 障害であり、ネットワークで応答が失われた場合ではない。

# カード CSV の金額欄が空欄のとき、金額0として黙って無視される: 実装前の期待記録

作成: 2026-11-05（コード・テストを書く前の期待の記録。実装後にこの節を書き直さない。期待が誤っていた場合は末尾に日時と理由を追記する）。

## 目的

カード形式（`signedAmount` の1列だけで金額を持つ形式）で、金額欄が空欄の行は「金額が不明」であって「金額0」ではない。いまは空欄が0円として読まれ、取引が `ignored`（残高照会などの行）に回るだけで、`errors` に入らない。そのためファイルは成功し、不明な金額の利用明細が黙って落ちる。

元コードの根拠（読取のみ。Claude は実行していない）:

- `src/lib/statements/values.ts:6-9`: `parseYen` は NFKC 正規化と `trim()` の後が `""` なら `null` を返す（ASCII 空白・全角空白・クオート内の空欄はここで `null` になる）。
- `src/lib/statements/parse.ts:203-205`: 符号付き金額の分岐が `signed = parseYen(cell(r, header.signedAmount)) ?? 0;`。`null`（空欄）が 0 に落ちる。
- `src/lib/statements/parse.ts:208-211`: `signed === 0` の行は `ignored.push({ line, reason: "金額が0（残高照会などの行）" })` して `continue`。
- 結果: `errors` が空のまま `import.ts:87` を通り、`importRows` が呼ばれ、空欄の行は `ignored` として記録されるだけになる。

「明細を黙って捨てない」「元明細と処理結果の件数・金額を照合する」（`docs/development-rules.md`）に反する。

## 期待する動作（修正後）

1. カード形式（`hasSplitColumns` が偽で `signedAmount` 列を使う形式）で、金額欄が空欄の行は `errors` に入れる。`rows` にも `ignored` にも入れない。
   - 空欄の定義は `parseYen` が `null` を返すもの: 空文字、ASCII 空白だけ、全角空白だけ、クオートされた空欄（`""`、`"  "`）。
2. エラーの行番号は CSV 上の物理行番号（見出し行を1行目として数える）。文言（日本語）は `金額が空欄です` で始め、金額0の行ではなく金額が不明であることが分かる説明を続ける（テストは `金額が空欄` の部分一致で確認する）。
3. ほかの行は通常どおり解釈する（エラーのある行が混ざっても `rows`/`ignored` の対象は変わらない）。`sourceRowCount` は `rows + ignored + errors`（見出しより後の空でない行数）のまま。
4. 取込（`importStatementCsv`）は既存どおり `errors` が1件でもあれば `importRows` を呼ばず、`recordFailure` を**1回**呼び、行番号つきの理由と `sourceRowCount` を渡す。
5. 明示的な `0`、全角の `０` は従来どおり金額0として `ignored`（理由は「金額が0」）。エラーにしない。
6. 正の金額は支出、負の金額（`-300`）は返金（入金）。従来どおり。
7. 金額が書式として読めない場合（`abc` など）は `parseYen` の既存エラーのまま。

## エラー

| 入力（カード） | 結果 |
| --- | --- |
| 金額欄が空文字 / ASCII 空白 / 全角空白 / `""` | 該当の物理行に `金額が空欄です…`。`ignored` に入れない |
| 空欄の行と正常な行が混在 | 空欄の行だけエラー。正常な行は `rows` に残る。取込側はファイル全体を失敗にする |

## 架空の具体例

BOM 付き UTF-8 の合成データ。1行目は見出し。

```
利用日,利用店名,利用金額
2026/11/01,架空店A,980
2026/11/02,架空店B,
2026/11/03,架空店C,-300
```

- 期待: `errors = [{ line: 3, message: "金額が空欄です…" }]`、`rows` は2行目・4行目、`ignored` は空、`sourceRowCount` 3。取込では `importRows` を呼ばず、`recordFailure` を1回（`sourceRowCount` 3、line 3）。

上の例の3行目の金額欄は、空文字、`   `、全角空白、`""` のどれでも同じ結果になる（テストは4通りを確認する）。

| 入力 | 期待 |
| --- | --- |
| カードで金額 `0` / 全角 `０` | `ignored`（金額が0）。エラーなし |
| カードで `980` / `-300` | 支出980 / 返金（入金）300 |
| 銀行で出金・入金がともに空欄 | `ignored`（金額が0）。エラーなし |
| 銀行で出金だけ・入金だけが空欄 | 値のある側で取引になる。エラーなし |

## 実装の説明（追記: 2026-11-05。上の期待は書き換えていない）

### 変更

`src/lib/statements/parse.ts:203-210`（符号付き金額の分岐のみ）。

- 変更前: `signed = parseYen(cell(r, header.signedAmount)) ?? 0;`
- 変更後: `parseYen(...)` の結果を `parsed` に受け、`parsed === null` なら `金額が空欄です（金額0ではなく金額が不明な行です。明示的な0とは区別します）` を投げる。それ以外は `0` を含めてそのまま `signed` に代入する。

### なぜファイル全体が拒否されるか

投げたエラーは既存の行ごとの `catch`（`parse.ts` の `errors.push({ line, message })`）に入る。`rows`/`ignored` には入らない。`import.ts` は `errors` が1件でもあれば `importRows` を呼ばず `recordFailure` を1回呼ぶ既存の関門を通るため、新しい分岐や変更は不要。不明な金額の行を残したまま他の行だけ取り込むことはしない。

### 変わらないもの

- 明示的な `0` / `０`: `parseYen` は `0` を返す（`null` ではない）ので従来どおり `signed === 0` で `ignored`。
- 返金（負の金額）: 符号の扱いは変更なし。
- 銀行形式: `hasSplitColumns` の分岐（`parse.ts:196-202`）は未変更で、共有の `parseYen` / `values.ts` も未変更。両方空欄 = 0 = `ignored` のまま。残高欄の `parseYen` も未変更。
- 既存データ: 修復しない。すでに `ignored` として取り込まれた空欄の行は別作業（Ken の判断が必要）。

# トップ画面（担当顧客一覧）の読込失敗表示の修正（初期リリース前の堅牢性）

対象: `src/app/page.tsx` の `HomePage`（読み取り専用。DB・スキーマ・RLS・RPC・会計方針・依存関係は変更しない）。

## 実装前の期待記録（2026-11-04、コード・テストを書く前の記載。書き換えない）

### 目的
トップ画面で、クライアント作成・顧客一覧の取得・件数の取得・応答の検証のどれかが失敗したときに、例外の中身を画面へ出さず、固定の日本語メッセージで「読めなかった」ことを示す。「担当顧客がいない（真に空）」と「読めなかった」を利用者が取り違えない表示にする。

### 現状の問題（コードで確認済み）
- `catch` で `error.message`（Error 以外は `String(error)`）をそのまま画面に出している。Supabase のエラー文・zod の検証文・内部情報が漏れ得る。
- `createUserClient()` が `try` の外にあり、失敗するとトップ全体が Next.js 既定のエラー画面に落ちる（固定文言の表示にならない）。
- 失敗時も見出し付きの空の表の枠を描く。顧客詳細画面（`src/app/customers/[customerId]/page.tsx`）は失敗時にリンク・表を出さないため、挙動が揃っていない。

### 入力と具体例（架空）
- クライアント作成が `Error("sk-secret-INFRA-token 秘密商事")` で失敗。
- 顧客一覧の取得が失敗、件数の取得が失敗、顧客行の形が不正（`id` が数値など）で zod 検証が失敗。
- `throw "sk-secret-NONERROR 秘密商事"`（Error ではない値）。
- 正常: 顧客 2 社（A 社は確認待ち 3・保留 0 ほか、B 社は全て 0）。
- 真に空: 顧客 0 件・件数 0 件。

### 予測する出力
- 失敗（上のどれでも）: 見出し＋固定のエラー文のみ。文言は「顧客一覧または確認待ち件数を読み込めなかったため表示できません」『担当顧客がない』『確認待ちが 0 件』を意味しません「時間をおいて再読み込み」。顧客名・顧客へのリンク・表・件数（0 も `—` も）・「担当している顧客がありません。」は出さない。例外の中身・顧客データは出さない。
- 正常: 従来どおり表・顧客名・`/customers/{id}` のリンク・件数（0 は `0` と表示）。
- 真に空: 従来どおり空の表の枠＋「担当している顧客がありません。」（エラー文は出さない）。
- 顧客一覧の並び（`name`→`id` 順、`fetchAll` でページ分割）・件数の取得方法は変更しない。

### 例外・失敗時の扱い
- 例外の種類（Error／非 Error）を問わず同じ固定文言。生の例外をログへ出さない（ログ追加もしない）。
- 失敗は 404 にしない（`notFound` は使わない）。

### 変更しない範囲
スキーマ・マイグレーション・RLS・ポリシー・`fetchAll`・`loadPendingCounts`・顧客詳細画面・承認／取込の動作・権限・依存関係。RLS による担当顧客の絞り込みは従来どおり DB 側（`createUserClient` の権限）で行う。

## 実装メモ（実装後に追記）
（2026-11-04 追記。上の期待は書き換えていない。）

### データの流れ（`src/app/page.tsx`）
- `createUserClient`・顧客の `fetchAll`・`loadPendingCounts`・zod 検証を 1 つの `try` に入れた（`src/app/page.tsx:16-24`）。どれが失敗しても `catch` に入り、例外を束縛も参照もしない（`catch {` のみ。ログも出さない）。
- `catch` は見出し＋固定のエラー文だけの `<main>` を `return` する（`src/app/page.tsx:24-34`）。表・顧客リンク・件数・「担当している顧客がありません。」には到達しない。顧客詳細画面の失敗表示と同じく、404 にはしない。
- 成功時は従来どおり表を描く。件数は `counts.get(...)` を直接使う（失敗時の `—` 表示の分岐は不要になり削除）。「顧客なし」は `customers.length === 0` のときだけ（`loadError` 判定は不要になり削除）。これで「真に空」のときだけ出る。
- 顧客取得の `order("name").order("id")` と `fetchAll` によるページ分割、`loadPendingCounts` の実装、`createUserClient` の権限（RLS）は変更なし。

### 判断と影響
- 変更はトップ画面の失敗時表示のみ。業務データ・権限・承認・状態遷移・DB は変更なし。
- 以前は空の表の枠と生の例外文が出ていた（訂正: `—` のセルが実際に出ていたわけではない。`Promise.all` の失敗で `customers[]` が空のままだったため、表に行がなかった）。今後は固定文言のみ。利用者が見る情報は減るが、原因の調査はサーバー側の手段（別途）に依存する。本修正でログは追加していない。
- 副次的変化: クライアント作成の失敗が、Next.js 既定のエラー画面ではなく固定文言になる。

### テスト
- `tests/unit/home-page.test.ts`（`fetchAll`・`loadPendingCounts`・`createUserClient` をモック）:
  - 失敗 5 種（クライアント作成／顧客取得／件数取得／スキーマ検証／Error ではない値の throw）で、固定文言があり、秘密の目印・顧客名・表・`<td`・`—`・顧客リンク・「顧客なし」がないこと。
  - クライアント作成失敗時に取得処理を始めないこと。
  - 正常: 顧客 2 社の名前・リンク、非 0 と 0 の件数の並び（確認待ち・保留・重複の疑い・未判定）、エラー文・「顧客なし」・`—` がないこと。
  - 真に空: 「担当している顧客がありません。」があり、エラー文がないこと。
- 限界: ここでは未実行（テスト・lint・型検査とも）。実 DB・RLS・ブラウザは通らない。`renderToStaticMarkup` の文字列一致（`<td class="num">…`）は React の出力形式に依存する。実行は Codex の独立確認に委ねる。

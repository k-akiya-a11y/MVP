# 顧客別の明細一覧（読取専用）: 実装前の期待記録

作成: 2026-11-04（実装前）。実装後にこの節を書き直さない。期待が誤っていた場合は、末尾に日時と理由を追記する。

## 目的

明細CSVのアップロードで結果が分からなかったとき、画面は取引の一覧を確認するよう案内する（`src/lib/statements/upload-result.ts` の `UPLOAD_UNKNOWN_MESSAGE`）。しかし承認画面の一覧は「候補あり（proposed）・保留（on_hold）」と重複の疑いだけで、取り込んだばかりの未判定（new）や、承認・却下・重複済みの明細は見られない。顧客ごとに既存の `bank_transactions` を状態を問わず読むだけの画面 `/customers/[customerId]/statements` を追加し、承認画面とアップロード欄の取込の記録リンクの隣から辿れるようにする。

## 入力

- URL の顧客ID、任意の `?page=N`（確認の履歴・取込の記録と同じ `parseHistoryPage`。不正・範囲外・複数指定は 1）。
- ログイン中の担当者の権限（`createUserClient`、RLS）。`service_role` は使わない。
- 読む表は `customers`、`bank_transactions`、`wallets`（口座名）。列は `20261020000300` で確認したものだけ。状態は `new / proposed / approved / registered / on_hold / rejected / duplicate_suspected / duplicate` の 8 つ。

具体例（架空）: 顧客「テスト商事」に 10-03 の明細が 3 件。(a) 10-03 出金 3,000円「ＡＢＣ商店」状態 new、(b) 10-03 入金 10,000円 状態 approved、(c) 10-02 出金 500円 状態 duplicate。

## 予測する出力

- 並びは `txn_date` 降順、同日は `id` 降順（明示指定）。1 ページ 50 件。前へ／次へのリンクだけ。検索・絞込・書込操作なし。
- 各件: 取引日、入金／出金、金額（円、桁区切り）、摘要、口座名（顧客内の口座のみ。読めなければ「名前を読めません」と ID）、状態（日本語）、明細ID、取込ID、重複の疑いなら元の明細ID。
- 状態の日本語:
  - new「未判定（仕訳候補は未作成）」
  - proposed「仕訳候補あり（人の確認待ち）」
  - approved「承認済み（freee への登録は、この記録では確認できていません）」
  - registered「freee 登録済み（記録上）」
  - on_hold「保留」
  - rejected「却下」
  - duplicate_suspected「重複の疑い（人の確認待ち）」
  - duplicate「重複として除外済み」
- 承認と freee 登録は別の状態として示す。AI の失敗理由・「判定できなかった」などは作らない。new は「まだ判定されていない」だけを意味し、失敗や不可の意味にしない。
- 例の (a)(b)(c) は日付降順・同日は ID 降順で並び、それぞれの状態が日本語で出る。

## 例外・失敗時の扱い

- 顧客IDが UUID でない、または RLS で顧客が見えない: 何も読まず 404。
- 読込エラー・応答の形式不正・未知の状態・他の顧客の行や口座の混入・ID の重複・金額が正の安全な整数でない・日付や入出金が不正: 固定の汎用エラー文のみ。空の一覧にはしない（0 件とは別の表示）。
- 0 件（1 ページ目）: 「明細はこの画面ではまだ見つかりません」（取り込まれていないことの証明ではない旨）。2 ページ目以降で 0 件: 範囲外の案内と 1 ページ目へのリンク。
- 口座が読めない: 行は残し、ID と「名前を読めません」を出す。
- サーバーの 1 回の応答上限で切れても、必要な件数に届くか空応答になるまで続けて読む。表示できる最終ページ（10000）より古い明細は、次へのリンクを作らず「辿れない」と明示する。
- 結果不明のままの取込は不明のまま。この画面に明細がないことは「取り込まれていない」証明ではないと書く。

## 動作の要約とロールバック

動作（初回リリース、読取専用）:

- 担当者は承認画面とアップロード欄の 2 つのリンクから、顧客ごとの明細一覧を状態を問わず見られる。書込操作はない。

ロールバック:

- 読取専用のため、2 つのリンクを外し、新しいページ・ローダー・テストを削除すれば元に戻る。
- DB のロールバックは不要（スキーマ・データは変更していない）。

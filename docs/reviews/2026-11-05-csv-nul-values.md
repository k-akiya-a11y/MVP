# 日付・金額・残高の NUL（U+0000）が、エラー文言経由で取込失敗の記録を壊す: 実装前の期待記録

作成: 2026-11-05（コード修正前の期待の記録。実装後にこの節を書き換えない。誤りがあれば末尾に日時と理由を追記する）。製品コードは未変更。Claude はコマンド・DB・AI を実行していない。

## 目的

`src/lib/statements/values.ts` の `parseYen` / `parseStatementDate` は、NUL を含む入力を正しく拒否するが、エラー文言に元の文字列（`"${raw}"`）をそのまま入れるため、文言に実際の NUL が残る（`values.ts:20,24,36`）。`parse.ts` の行ごとの `catch` はこの文言を `errors` に入れ（`parse.ts:232-234`）、`import.ts:63-69` の `fail` が `recordFailure` に渡して JSONB に保存する。PostgreSQL の JSONB は U+0000 を拒否する（[公式文書](https://www.postgresql.org/docs/current/datatype-json.html)。実 DB では未確認）ため、診断の記録が失敗し、「どの行が読めなかったか」が利用者にも取込記録にも残らない。直前の摘要の NUL（`2026-11-05-csv-nul-description.md`）と同じ種類の問題が、摘要以外の列で残っている。

## 期待する動作（修正後）

1. `parseYen` / `parseStatementDate` は、入力に U+0000 が1文字でもあれば、**元の入力を文言に含める前に**、固定の日本語エラーを投げる。文言は `NUL` と対象（`日付` または `金額`）を含み、実際の NUL も `\u0000` の表記も含まない。位置（先頭・途中・末尾・NUL だけ）は問わない。
2. NUL を取り除く・置換する・0として読む・切り捨てることはしない。拒否だけ。
3. パーサ（銀行・カード）: 日付・出金・入金・残高・符号付き金額（返金を含む）の NUL は、その物理行のエラーになる。金額0に見える値（`0` + NUL、NUL と `0`）も `ignored` にせずエラー。隣の正常な行は `rows` に残り、値は変わらない。`sourceRowCount` は `rows + ignored + errors`。
4. 取込: `errors` があれば `importRows` を呼ばず、`recordFailure` を1回だけ、NUL を含まない `errors` で呼ぶ。`recordFailure` が NUL を含む `errors` を拒否するモックでも、`{ ok: false, failureRecordId, errors }` を返し、行番号つきの診断が残る。
5. NUL がない入力は変えない: 有効な日付・金額・返金（`△`・括弧）・空欄（`null`）、NUL のない不正値のエラー文言（元の文字列を含む）は従来どおり。

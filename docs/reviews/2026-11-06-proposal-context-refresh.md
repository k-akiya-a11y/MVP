# 提案の実行: 顧客文脈を明細ごとに読み直す: 実装前の期待記録

作成: 2026-11-06（コードとテストを書く前）。実装後にこの節を書き直さない。期待が誤っていた場合は、末尾に日時と理由を追記する。

## 目的

`runProposalJob`（`src/lib/proposals/run.ts`）は、顧客ごとの `CustomerContext`（ルール・メモ・過去仕訳・マスタ）を `Map` に入れ、**1回の実行の間ずっと**使い回している。そのため、同じ実行の中で同じ顧客の 2 件目以降の明細は、実行の途中で人が確定した過去仕訳、無効化・編集されたルール、メモの変更を見ない。`docs/design.md` は「人の確認は次の明細から反映される」としており、この動作はそれに反する。

この作業は、実行全体での文脈の再利用をやめ、**判定を始める明細ごとに最新の文脈を読む**ことだけを行う。

## 期待する動作（修正時の仕様）

- 借りた明細 1 件ごとに `store.loadCustomerContext(txn.customerId, deps.today)` を 1 回呼ぶ。実行内の保持（`Map`）は廃止する。新しいキャッシュ・保持は作らない。
- 呼ぶ位置は従来の最初の読込と同じ（`attempted` 加算の後、時間の予算の再確認・`confirmClaim`・予算の再確認より前）。
- 読んだ文脈はその 1 件の判定にだけ使い、次の明細には渡さない。

## 具体的なケース

| ケース | 期待 |
|---|---|
| 同じ顧客の 3 件。読込のたびに別の文脈（ルールの版 1 → 版 2 → 無効化）を返す | 各明細はその時点の文脈で判定される。1 件目は版 1、2 件目は版 2、3 件目はルール一致なしで AI を呼ぶ。読込は 3 回 |
| 同じ顧客の 2 件。2 件目の読込では過去仕訳・メモが変わっている | 2 件目の判断ログ（`past_entry_ids`・`note_versions_used`）は新しい文脈に基づく |
| 顧客 A・B・A の順 | 読込は A・B・A の 3 回（顧客 ID を引数に）。各明細は自分の顧客の文脈だけを使う。顧客間で文脈が混ざらない |
| 2 件目の読込が失敗 | 2 件目は失敗として数え、1 件目の文脈も AI も使わない（AI 呼出しは 1 件目の 1 回だけ）。1 件目の記録は保たれ、3 件目以降は続く。2 件目の貸出しは返す |
| 2 件目の読込の間に予算が尽きた | AI を呼ばず、失敗には数えず `truncated` で打ち切り、貸出しを返す（従来どおり） |
| 2 件目の読込の後、`confirmClaim` が false | AI を呼ばず失敗として数える（従来のメッセージ）。読込はその前に行われている |
| 読込の失敗・予算・所有の確認 | 既存の単体テストの期待（貸出しの返却、`settled` の扱い、タイムアウトで貸出しを返さない等）は変わらない |

## 例外・失敗時の扱い

- 読込の失敗は従来どおり、その明細だけの失敗（`failures` に追加、`attempted` に含む）。実行は続く。古い文脈への退避はしない。
- 追加の再試行・フォールバックはしない。

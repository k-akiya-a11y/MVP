# 不正な貸出し行の返却: 実装前の期待記録

作成: 2026-11-06（テストを書く前）。実装後にこの節を書き直さない。期待が誤っていた場合は、末尾に日時と理由を追記する。

## 目的

`supabaseProposalStore.claimPendingBatch`（`src/lib/proposals/store.ts`）は、RPC `claim_pending_proposal_batch` が成功して明細を貸し出した後、返された配列を `z.array(txnRow).parse(data)` で検証する。ここで 1 行でも不正（例: `amount` が整数でない）だと例外を投げ、呼出し側（`run.ts`）が `run.owned` に登録する前に抜けるため、DB 側では貸出し済みの明細が返却されず、`CLAIM_LEASE_SECONDS`（600 秒）の間、他の実行に渡らない。

この不具合を、**修正の前に**失敗するテストとして固定する。この作業では本番コードを変更しない。

## 承認済みの最小設計（修正時の仕様）

- 捕捉するのは、RPC が**成功した後**の `z.array(txnRow)` の検証失敗だけ。
- 返却対象 ID は、返却値の**生の配列**の各行から、検証の成否と無関係に、`id` が正しい UUID の文字列であるものだけを取り出す。重複は除く。
- 既存の `release_proposal_claims` を、**このストア自身の `owner`** と上の ID で呼ぶ。応答の中の owner は信用しない。所有者単位の全件返却はしない。UUID でない値は渡さない。
- 配列全体で全か無か: 1 行でも不正なら、返却値のうち ID を特定できる行（正常な行と不正な行の両方）をすべて返却する。呼出し側には 1 行も渡っていないため。
- 特定できる ID がなければ何も返却せず、TTL に任せる。
- 返却がエラー・例外になっても、**元の検証エラー**を投げる（返却の失敗で置き換えない）。成功を装わない。
- RPC 自体のエラー・結果不明（非配列を含む）では、推測の返却をしない。
- SQL 側 `release_proposal_claims` の所有者条件が、所有者が変わった明細を守る。マイグレーションは不要。

## 入力（すべて架空データ）

- ストアの owner: `store-owner`（固定。`supabaseProposalStore(client, "store-owner")`）。
- 実ストアに、`rpc(name, args)` を記録して固定の結果を返す偽のクライアントを渡す（DB・ネットワーク・AI は使わない）。
- 正常な行: `id`（UUID）・`customer_id`・`wallet_id`・`txn_date`・`amount`（整数）・`direction`・`description`。
- 不正な行: 正常な行の `amount` を `"12.5"`・`"abc"`・`null` などにしたもの。

## 予測する出力

| ケース | 期待 |
|---|---|
| 不正な `amount` で ID は正しい 1 行 | 元の検証エラー（`ZodError`）を投げる。RPC は `claim_pending_proposal_batch` → `release_proposal_claims`（`p_owner: "store-owner"`, `p_ids: [その ID]`）の順に 2 回 |
| 正常行と不正行の混在（ID が重複する行を含む） | 検証エラーを投げる。返却は 1 回、`p_ids` は正常行と不正行の ID を初出順に重複なしで |
| ID が UUID でない・欠落・`null` の行、行が `null`、配列でない結果 | 検証エラーを投げる。返却 RPC は呼ばない（広い返却をしない）。UUID でない値は `p_ids` に入れない |
| 正しい UUID の不正行と、UUID でない ID の行の混在 | 正しい UUID の ID だけ返却 |
| 応答の行に別の owner の値がある | `p_owner` は常に `store-owner`。応答の値は使わない |
| 返却がエラー（`{ error }`）を返す | 元の検証エラーを投げる。返却のエラーメッセージは含まない |
| 返却 RPC が例外を投げる／拒否する | 元の検証エラーを投げる。返却の例外に置き換わらない |
| 正常な行だけの配列 | 変換された明細を返す。RPC は 1 回だけ（返却なし） |
| 貸出し RPC 自体がエラー | 既存のエラーを投げる。RPC は 1 回だけ（返却なし） |

## 例外・失敗時の扱い

- 返却は最善努力。失敗しても元のエラーを隠さず、成功も装わない。
- 現状（修正前）では、返却を呼ばないため、返却を期待するテストは**失敗する**はずである。失敗しないものは現在の正しい挙動を固定するもの（返却なし系）。期待値を弱めて通さない。

#### 初期データ

- マイグレーション 17 件を適用した。
- 合成パスワードの Auth ユーザー 3 名を投入した。管理者は 2 顧客、スタッフと別スタッフはそれぞれ 1 顧客を参照できた。

#### 実ブラウザでの結果

1. スタッフは、割り当てられた顧客のみ表示された。
2. CSV の選択: ネイティブのアクセシビリティ上のラベルは、DOM 上の「Choose File」と異なっていた。最初に日本語ラベルで指定した Playwright の filechooser はタイムアウトしてリセットされ、送信は行われなかった。DOM 上の「Choose File」を正しく指定して `setFiles` を実行すると成功し、スクリーンショットで `ui-validation-bank.csv` が選択されたことを確認した。アップロードは 1 回で、結果は 4 行・371,800 円、登録 4、スキップ 0 だった。
3. ルールのみの提案(HTTP 200): attempted 4、processed 3(high 2、low 1)。4 件目は AI 認証情報がないため new のまま残った。これは想定どおりで、実 AI は使っていない。
4. スタッフには承認・修正のコントロールが表示されなかった。理由必須の保留は成功し、対象は 9020 だった。
5. 管理者は、保留行を除く 8800 のみを一括承認した。low の 350000 は、勘定科目を 101 から 102、税区分を 21 から 2 に理由付きで修正した。説明文のリテラル `$& $$ $1` は保持された。
   - 注意: 選択した「対象外」のラベルは、実際には ID 2 であり、0 ではない。合成の入力理由には tax 0 と書いたが、それは 0 であることの証明にならない。今回は tax 0 に関する主張を行わない。
   - 税区分をクリアすると、保存は無効になった。
6. 履歴(3 件)には、スタッフ・管理者、理由、変更前後の値が表示された。取り込み履歴は 1 件で、4 行・371,800 円と一致した。明細は 4 件で、approved 2、on_hold 1、new 1 だった。
7. 既存の verify-state SQL を独立に実行した結果は、ai_decisions 3、human_reviews は approve 1・correct 1・hold 1、execution_logs 0 だった。
8. 別スタッフは 2 番目の顧客のみ参照できた。最初の顧客の base、history、imports、statements、rules、notes、past-quality の各 URL はすべて 404 を表示し、サーバーログも 404 だった。
9. ヘルパーでのログアウトは 303 を返し、アプリは `localhost:3100/login` にリダイレクトして Google ボタンを表示した。実 Google は使っていない。

- 最初の非 PTY 実行は EOF で即座に解放され、終了コード 0 だった。この時点ではブラウザのリクエストは出ていない。以降は PTY で動作した。

## 時系列と結果

1. 既知の拒否: 画面が STALE を表示したまま、別のローカル管理者 RPC で承認した。ブラウザで承認すると `すでに確認済み（approved）` が表示され、承認ボタンは再び有効になった。
2. 単独（NORMAL の行ロック保持中）: 4 件を選択して単独承認をクリックすると、現在の選択が除かれて 3 件になった。単独・まとめて・却下・編集は無効化され、Shift+A と x は抑止された。リクエストは 8448ms 後に 500 で終了した。サニタイズ済みの「結果不明」メッセージが出て、タブ切替・再選択・a / Shift+A / x の後も残った。DB は NORMAL が proposed で reviews 0、STALE が approved で 1、BULK 3 件が proposed で 0、実行 0。ロックは終了コード 0 で解放した。
3. 単独の復旧: 再読み込みで警告が消え、操作が再び有効になった。再読み込み直後の最初の承認クリックは効果がなく、POST も DB の変更もなかった。リトライ前の UI とログは観測した。2 回目のクリックで通常どおり承認され、reviews は 1 件になった。
4. まとめて 3 件（BULK-1 のロック保持中）: まとめて承認をクリックすると、書き込み系ボタンはすべて無効化され、a / x / Shift+A は抑止された。リクエストは 8314ms 後に 500 で終了した。「結果不明」が表示され、選択は 0 に解除された。3 件を再選択しても単独・まとめては無効のままで、DB の変更はなかった（BULK は 3 件とも proposed）。ロックは終了コード 0 で解放した。
5. まとめての復旧: 再読み込みで警告が消え、確認待ちは 3 件だった。3 件を選択して承認すると成功し、確認待ちは 0 になった。
6. 最終の DB: 5 件すべて approved、reviews 各 1 件、実行 0 件、障害はオフ。

HTTP POST: 既知の拒否 200、単件の送信待機中 500、通常の成功 200、一括の送信待機中 500、まとめての成功 200。

## 判断の留保

厳密な SQLSTATE やタイムアウトの原因は調べていない。観測したのは DB のロック待ちと 500 だけであり、原因をそれ以上は断定しない。

## 限界

- 実ブラウザと使い捨ての合成 PostgreSQL での検証であり、実 Supabase は対象外。ロック待ちとサーバー障害の検証であり、コミット後に応答だけが失われるケースではない。
- 複数タブ・複数デバイス間の冪等性、全キー・エディタ・ロールの組み合わせ、Google OAuth、実 AI、実 DB は対象外。
- スクリーンショットはブラウザツールで見ただけで、ファイルとしては保存していない。

# 認証コールバックの実HTTP検証: 証拠記録

作成: 2026-11-06。Codex が隔離したローカル環境で実行を立ち会い確認した結果の事実記録。製品コードは変更していない。全体のリリース承認ではない。

## 目的

認証コールバック（`code` 交換、スタッフ判定、リダイレクト先の制御）を、実際の HTTP リクエストと、ローカルの実 Auth・PostgREST・Postgres に対して確認する。

## 環境

- 実行: Codex が立ち会い確認した。
- 隔離したローカル Docker 環境: Auth / PostgREST / Postgres 17.6。マイグレーション 17 件適用。
- 合成データ: ユーザー 3 名、顧客 2 件。
- ヘルパー（リポジトリ外）: `local-ui-validation-20261103/scripts/auth-callback-http-check.mjs`。
- アプリ: `next dev`、ポート 3100。

## 検証内容と結果

最終結果は **45/45 合格**。

| 観点 | 確認した結果 |
| --- | --- |
| `code` なし | 307 でログイン画面へ。失敗として扱い、コード交換は行わない。 |
| スタッフ（PKCE 交換をモック） | 実ローカルの `getUser` と RLS を通過。セッション Cookie が発行され、ホーム画面が 200。 |
| 許可ドメインだが未登録 | スタッフ行なし。実 `signOut` が 1 回呼ばれ、Cookie が削除され、`not_staff` でログイン画面へ。 |
| 許可外ドメイン | `signOut` が呼ばれ、Cookie が削除され、`domain` でログイン画面へ。 |
| 外部 `next` パラメータ | 無視され、リダイレクト先は想定どおりの正確な値。 |
| RLS | スタッフのセッションは顧客 total 1 件・own staff 1 件を見られる。未登録ユーザーと部外者（outsider）はそれぞれ顧客 0 件・own staff 0 件。スタッフ表の総数は 3 件のまま変化なし。 |

各実行で、作成した追加ユーザー 2 件のうち 2 件を削除した（2/2）。

## 初回の失敗と修正

- 初回は **38/45**。オリジン関連の 7 件の検証が失敗した。
- 原因: ヘルパーが `127.0.0.1` への TCP 接続で送信していた一方、`next dev` は `localhost` を正規 URL として扱うため、オリジンが一致しなかった。
- 対応: Claude がヘルパーを修正した。明示的に `Host: localhost:3100` を送り、期待するオリジンを `localhost` の正確な値にした。**製品コードの不具合ではなく、製品コードは変更していない。**
- 修正後の再実行で 45/45 合格。

## 検証方法の性質

- パスワードで作った合成セッションは、ローカルの実 Auth によるもの。
- モックしたのは PKCE のトークン交換のみ。ワンタイムの `code` と S256 を使用。
- SSR による Cookie の生成は、外部 OAuth 通信なしで行われた。

## 限界（主張しないこと）

- Node の HTTP クライアントと Cookie jar を使っており、実ブラウザではない。
- 実際の Google OAuth、2 要素認証は検証していない。
- 本番の実 Cookie は検証していない。
- JWT の即時失効は検証していない。
- Host ヘッダーに関するセキュリティ監査は行っていない。
- 前回の 1788 件の単体テストの結果は、今回は再実行していない。
- `node --check`（ヘルパーの構文チェック）は合格した。

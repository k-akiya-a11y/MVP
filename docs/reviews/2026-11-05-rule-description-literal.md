# ルールの摘要の雛形が、明細の摘要の `$` を特殊記号として解釈する: 実装前の期待記録

作成: 2026-11-05（テストを書く前の期待の記録だけ。本番コードは未変更）。実装後にこの節を書き直さない。期待が誤っていた場合は、末尾に日時と理由を追記する。

## 目的

`renderDescriptionTemplate`（`src/lib/rules/match.ts:28-34`）は、顧客ルールの摘要の雛形（設計書5章「摘要の雛形」）を埋める。`{description}` の置換は `replaceAll("{description}", txn.description)` で、**置換後の文字列に銀行明細の摘要をそのまま渡している**。JavaScript の文字列置換は、置換後の文字列の `$` を特殊記号として解釈する。そのため、摘要に `$` が含まれると、摘要の文字がそのまま入らない（**現状の実装の読解による予測。Claude は実行していない**）。

| 摘要に含まれる記号 | JavaScript が解釈する意味 | 雛形 `明細:{description}:終` に摘要 `A<記号>B` を入れたときの現状の予測 |
| --- | --- | --- |
| `$&` | 一致した文字列（`{description}`）に置き換わる | `明細:A{description}B:終` |
| `$$` | `$` 1文字になる | `明細:A$B:終` |
| `` $` `` | 一致箇所より前の文字列が入る | `明細:A明細:B:終` |
| `$'` | 一致箇所より後の文字列が入る | `明細:A:終B:終` |

期待は、**どの摘要でも、摘要の文字がそのまま（1文字も増減・変形せず）入ること**。例: 雛形 `明細:{description}:終`、摘要 `A$&B` → `明細:A$&B:終`。

この摘要は、ルールに一致した取引の「提案する摘要」になり（`src/lib/proposals/propose.ts:83-86`）、そのまま AI 判断ログの `proposal.description`（`src/lib/audit/decision-log.ts:5-15,27`）に入る。担当者が承認画面で見る摘要と、承認後に freee へ登録される摘要の元になるため、勝手に変わった摘要を、本人が気づかないまま承認するおそれがある。

この段階では**期待の記録と、失敗するはずの回帰テストの追加だけ**を行う。本番コードは変えない。

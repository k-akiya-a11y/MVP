# 金額0の行の残高が不正でも、行ごと無視されてファイルが取り込まれる: 実装前の期待記録

作成: 2026-11-05（コード・テストを書く前の期待の記録。実装後にこの節を書き直さない。期待が誤っていた場合は末尾に日時と理由を追記する）。

## 目的

`parseStatementCsv`（`src/lib/statements/parse.ts:189-192`）は、金額が0（`signed === 0`）の行を、残高（`parse.ts:202` の `parseYen(cell(r, header.balance))`）を読む**前**に `ignored` へ入れて `continue` する。そのため、金額が0の行の残高欄が壊れていても（例: `"1,23"`、桁あふれの数字）エラーにならず、ファイル全体が取り込まれる。金額が0でない行の残高が壊れていれば、同じ値でもファイル全体が失敗になる。

「明細を黙って捨てない」「読取失敗には理由と追跡可能な記録を残す」「元明細と処理結果を照合する」（`docs/development-rules.md`）、および「1行でも読めない行があればファイル全体を取り込まない」（`import.ts` の方針）と、金額0の行だけ扱いが食い違う。残高は重複キーや照合に使うため、壊れた残高を持つ行を黙って通すと、後で原因を追えない。

注意: これは Claude が `parse.ts` を読んで確認した内容で、実行による再現はしていない（Claude はテストを実行しない）。

## 期待する動作

1. 金額が0の行でも、残高欄を `parseYen` で解釈する。書式が壊れた・安全な整数を超える残高は、その行のエラーにする（行番号つき）。
2. 1行でもエラーがあれば、既存どおりファイル全体を失敗とする。他の有効な取引行があっても取り込まない（`importRows` は呼ばない）。
3. 金額が0で残高が正しい行、または残高が空欄の行は、従来どおり `ignored`（行番号と理由「金額が0（残高照会などの行）」）に入れる。取引にはしない。
4. 残高の列が見出しにない形式・ファイル、または残高欄が空欄の行は、従来どおり有効（`balance: null`）。残高を必須にしない。
5. カード形式（符号付き金額、残高列なし）の金額0の行は従来どおり `ignored`。返金（負の金額）は従来どおり `income`。
6. 金額0の行でも、金額欄・日付欄の解釈エラーは従来どおり。この変更が足す検査は残高欄のみ。
7. `sourceRowCount` の定義（= rows + ignored + errors）は変えない。エラーになった金額0の行は `errors` に1件として数え、`ignored` には入れない。

## 実装の説明（Claude、2026-11-05。実行による確認はしていない）

製品コードで変更したのは `src/lib/statements/parse.ts` のみ。

- `parse.ts:190` 金額（`signed`）を決めた直後、`signed === 0` の判定（`parse.ts:191`）より前に `const balance = parseYen(cell(r, header.balance))` を置いた。壊れた残高・安全な整数を超える残高は `parseYen` が例外を投げ、既存の `catch`（`parse.ts:206-208`）で、その行の `errors`（行番号つき）になる。金額0の行は `ignored` に入らず、`continue` にも到達しない。
- `parse.ts:204` 取引行の `balance` は、同じ変数を再利用する（`parseYen` を2回呼ばない）。値は従来と同じ。
- 残高の列が見出しにない場合、`cell` は `""` を返し（`parse.ts:159`）、`parseYen("")` は従来どおり `null`（`values.ts` の仕様は未変更）。残高欄が空欄の行も同じく `null` で有効。残高は必須にならない。
- 検査の順序: 列数 → 日付 → 摘要 → 金額（出金・入金の両方に値がある場合のエラーを含む）→ 残高 → 金額0なら `ignored` → 摘要の空欄。金額・日付のエラーが先に出る点は従来どおり。金額0で摘要が空欄の行は、残高が有効なら従来どおり `ignored`。
- `sourceRowCount`（`parse.ts:210`）の式は未変更。エラーになった金額0の行は `errors` の1件として数えられ、`ignored` とは重ならない。
- カード形式（残高列なし）の金額0・`△0` は残高が `null` になるため従来どおり `ignored`、返金（負の金額）は `income`。

影響: 金額0かつ残高が壊れた行を含む CSV は、取り込まれずファイル全体の失敗として記録される（`import.ts` の既存方針どおり）。有効な入力（残高が正しい・空欄・残高列なし）の結果は変わらない。ただし、摘要が空欄で、かつ残高も壊れている行のように複数の不備が重なる入力では、先に報告されるエラーの優先順位が変わる可能性がある。すべての入力の動作が従来と同じとは主張しない。DB・権限・UI・依存関係への影響はない。すでに取り込まれたデータの修復は含まない。

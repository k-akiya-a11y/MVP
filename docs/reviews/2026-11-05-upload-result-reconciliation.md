## 目的

`submitStatementUpload`（`src/lib/statements/upload-result.ts:55-98`）は、2xx 応答を `successSchema`（同 19-31）で検証する。各項目が「0 以上の整数」であることだけを見ており、次の関係を見ない。

- `incomeTotal + expenseTotal` = `insertedAmountTotal + skippedAmountTotal + suspectedAmountTotal`
- 件数と金額の対応（件数 0 ならその分類の金額は 0、件数が 1 以上なら金額は正）

設計書の取込記録の契約（`docs/design.md` 80 行）は「読めた行の件数・金額（入金・出金別）と、その内訳（登録・取込済みのため読み飛ばし・重複の疑い）を残し、両者が一致することを DB の制約で確かめる」である。応答がこれと食い違うのに「成功」として要約を出すと、`docs/development-rules.md` の「元明細と処理結果の件数・金額を照合する。差異は説明できるまで未解決」に反する。

Codex の静的所見による。実行して確かめた事実ではない。

## 入力と期待する出力（架空データ）

基準の正常応答（`tests/unit/upload-result.test.ts` の `COUNTS`）: 登録 3 件 90,000 円・読み飛ばし 1 件 5,000 円・疑い 2 件 30,000 円（合計 125,000 円）、入金 100,000 円・出金 25,000 円（合計 125,000 円）、`ignoredCount` 1。

### 拒否する（`unknown`、固定文 `UPLOAD_UNKNOWN_MESSAGE`）

| 例 | 入金+出金 | 内訳の合計 | 期待 |
| --- | --- | --- | --- |
| 合計 600 円に対し内訳 599 円（登録 100・読み飛ばし 300・疑い 199） | 600 | 599 | `unknown` |
| 内訳が 1 円多い（疑い 201） | 600 | 601 | `unknown` |
| 内訳が大きく少ない／多い | 600 | 0／1,100 | `unknown` |
| 丸めで見逃す例: 入金 `MAX_SAFE_INTEGER`、出金 2、登録 `MAX_SAFE_INTEGER`・読み飛ばし 1 | 2^53+1 | 2^53 | `unknown`（浮動小数点の和では両方 2^53 に丸まって一致して見えるため、BigInt で比較する） |
| 件数 0 なのに金額が正（登録 0 件・60 円） | 合計は一致 | | `unknown` |
| 件数が 1 以上なのに金額 0 円（登録 1 件・0 円） | 合計は一致 | | `unknown` |
| 読み飛ばし／重複の疑いの件数と金額の食い違い（上の 2 通りを各分類で） | 合計は一致 | | `unknown` |

表示は固定文だけにし、応答の金額や件数は画面に出さない。fetch は 1 回だけで自動再送しない。

### 保持する（`success`、要約は従来どおり）

- 基準の正常応答（登録・読み飛ばし・疑い・`ignoredCount` を含む）。
- 完全再取込: 登録 0 件・0 円、読み飛ばしだけ。
- 重複の疑いだけ（登録 0・読み飛ばし 0）。
- 入金だけ・出金だけ。
- 金額 0 の行だけのファイル: 全件数 0・全金額 0、`ignoredCount` は 1 以上。
- 合計が `MAX_SAFE_INTEGER` ちょうどで一致するもの（BigInt 比較で正しく通る）。

### 変えない挙動

- 既知の登録前拒否（400・401・404・413）は固定文で `rejected`、422 は従来どおり。
- それ以外の 4xx・5xx・本文不正・通信失敗は `unknown`。
- 文字列の金額（`"600"` など）は成功にしない（`successSchema` は number のみ）。
- 負・小数・UUID でない `importId` は `unknown`。

## 例外・失敗時の扱い
